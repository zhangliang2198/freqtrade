# 市价开仓追价拦截（默认启用）

本检查实际拒单，不是观察或只记日志。普通买入和轮换买入共用
`_execution_is_safe()`，不改评分、仓位大小、杠杆、止损和退出条件。

## 规则与配置

在 `leader_squeeze` 对象中可以显式设置：

```json
{
  "entry_price_guard_enabled": true,
  "entry_price_max_deviation_atr": 1.0
}
```

为兼容现有配置，两项缺省值分别为 `true` 和 `1.0`，不增加新的必填字段。
因此现有配置直接加载本次代码后即启用真实拦截；没有 observe 模式。
开关类型错误，或倍数为布尔值、非数值、零、负数、NaN/Infinity 时，
在开仓执行检查中拒单并记录原因，不会自动降级放行。

```
买入上限 = 信号收盘价 + ATR倍数 × 信号之前的参考ATR
预计成交均价 > 买入上限 → 拒绝本次开仓
```

预计成交均价按本次订单数量与已有卖盘计算，不能只比较卖一价。
原价差、20档深度、滑点上限和5秒盘口时效检查仍必须通过。
`1.0` 是可调整的工程初值，不是经过收益回测证明的最优参数。

## 信号与时效

选币/轮换预检查（未传 `amount`）按当时最新已收盘主周期 K 线建立基准，
只使用本地 `DataProvider` 数据及现有 `_wilder_atr()`，不额外请求交易所。
参考 ATR 排除信号 K 线自身，历史长度沿用入场过热的历史上限；关闭
`entry_heat_max_penalty` 不会关闭本检查，也不要求其完整15日历史。

同一交易对、同一信号 K 线重复检查不抬高上限，历史数据修正或放宽
倍数也不能在同一信号内抬高上限；收紧倍数可以收紧上限。
基准在下一根主周期 K 线应收盘的时刻失效，不利用行情宽限时间续期。

实际下单确认（传入真实 `amount`）只能使用已有有效基准，不能现场重新
计算更高的买入上限。基准缺失、过期或系统时间回退到信号收盘前即拒单。
新 K 线必须经过新一轮预检查才能成为新基准。
盘口请求完成后再次检查基准时效，因此跨收盘边界的旧请求不能继续下单。

拦截发生在 `confirm_trade_entry()` 的 `_prepare_rotation_buy()` 之前，
不会因为此处拒单而将轮换推进为 buy_pending，也不会触发旧仓轮换卖出。
正常的独立止损和趋势退出不受影响。

## 日志与边界

拒单原因包含 `追价拦截`、预计成交均价、买入上限、信号收盘价、参考ATR、
偏离的ATR倍数和信号时间戳；最终确认仍沿用现有审计日志记录拒单。
示例：信号收盘100、ATR为2，上限102；预计成交106.04时拒单，即使相对
当前卖一106的盘口滑点只有约0.038%。

此检查是下单前基于盘口快照的**准入限制**，不是交易所限价委托；盘口检查
通过到市场订单成交之间价格仍可能变化，不能保证最终成交价不越过上限。
它可能减少追高成交，也可能错过快速上涨；本改动不承诺提升收益。

## 验证与回退

新增 `tests/strategy/test_leader_squeeze_entry_price_guard.py` 为离线源码级回归：
将实际执行方法、现有确认回调、已收盘K线校验和ATR方法放入隔离测试环境，
只替换外围账户/行情接口，不启动机器人、不发送真实订单。
可在具备 pandas 和 pytest 的环境运行：

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest --noconftest -o addopts= -q tests/strategy/test_leader_squeeze_entry_price_guard.py
```

原共享测试夹具显式关闭新检查，仅用于不提供OHLC/信号基准的旧策略单元
测试；不修改公共运行配置。新增回归专门验证默认启用、真正拦单、边界价格、
真实数量VWAP、跨K线、无效数据、普通/轮换确认和退出不受影响。

该隔离测试不替代完整 Freqtrade 测试套件、回测或模拟盘验证。
运行环境合并并加载新代码后才生效，本 PR 不自动合并、部署或重启。
需要撤销新增限制时，可在配置中显式设置 `entry_price_guard_enabled=false`
并按既有部署流程加载配置；原有风控不因此关闭。
